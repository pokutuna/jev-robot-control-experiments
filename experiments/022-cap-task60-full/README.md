# 022 骨組みを回して分かったことも渡し、LLM に task 60 の手順を書かせる

## 課題

021 と同じ知見 (`KNOWLEDGE: "017"`) で、運ぶ物を task 60 (左の黒いボウルをトレイへ) に替えて LLM に手順を書かせ、同じタスクの骨組み (018) と、知見を足す前の 020 と比べる。

"017" で足した知見のうち、ボウルを持っているときの固定カメラの答えのずれは、018 で task 60 そのものを回して測った値である。このため 022 は、別のタスクで分かったことを持ち込む比較ではなく、同じタスクで前に測ったずれを LLM に渡したときの比較になる。

## 仮説

LLM は、ボウルを持っているときの答えのずれを手順に取り入れ、020 (6/10) より多く成功する。ずれの値は同じタスクで測ったものなので、取り入れれば置く段の失敗は減る。

## 方法

021 と同じ `CaPPolicy`、`KNOWLEDGE: "017"`、LLM、上限で、init ごとに 1 本、計 10 本のプログラムを書かせた。プロンプトの全文は [programs/prompt.md](programs/prompt.md)。021 との違いは、指示文 (task 60) だけである。"017" の中身は [021 の方法](../021-cap-task61-full/README.md#方法) に書いた。

"017" には、018 の骨組みの 4 つ目の版で分かった、何も持たずにトレイの中心へ手首の画像で合わせると中心から 5〜8 cm 手前で (0, 0) と答えることは入っていない。"017" は骨組みの 3 つ目の版までの回し方で測った値で書いた。

```sh
uv run --env-file .env scripts/generate_programs.py experiments/022-cap-task60-full --inits 0-9
uv run --env-file .env scripts/run_experiment.py run experiments/022-cap-task60-full --inits 0-9
```

[results.md](results.md) の「掴む点への最短」は、タスクの定義に書いた掴む点 (ボウルの +y の縁) からの距離で、プログラムが掴む -y の縁からの距離ではない ([018](../018-skeleton-switch/README.md) と同じ)。

## 結果

[results.md](results.md) の表と、プログラムと記録から読んだ値を要約する。

- 成功 4/10 (init 0、6、7、8)。init 0 は、指を開いた後に手先を上げると、ボウルとトレイが一緒に 21.2 cm 持ち上がっていた。これを除くと 3/10。020 ("016") は 6/10 (同じく除くと 5/10)、018 の骨組みは 3/10
- 1 エピソード: 平均 50.1 回の判断、Jev の呼び出し 39.2 回 (16〜71)、761 step、入力 4.3 万トークン
- プログラムの生成: 1 本あたり出力 2.7 万トークン (考える分を含む)、費用は 10 本で 0.14 USD

掴む段は、10 本ともボウルの中心に合わせてから -y に 6 cm ずらして縁を掴む手順だった。左のボウルを掴んだ 8 回は、指を閉じた所がボウルの中心から x に -2.9〜+1.3 cm、y に -4.3〜-4.9 cm で、ボウルを 20〜23 cm 持ち上げた。残りの 2 回 (init 4、5) は右のボウルを掴んだ (後述)。

開く前に 3 cm 上げる知見は、10 本中 8 本が取り入れた。取り入れなかった init 0 は下ろして止まった所で指を開き、トレイを 21.2 cm 持ち上げた。init 8 は、トレイの上で下ろさずに、始めの高さで指を開いてボウルを落とした。

置く段の書き方は、次の 3 通りに分かれた。

| init | 置き場所に合わせる時機 | 置くときに足す動き | 成功 | 最後のボウルとトレイの中心 [cm] |
| --- | --- | --- | --- | --- |
| 6 | 持ったまま寄せる | 固定カメラが (0, 0) と答えた所から x に +10 cm | 成功 | x -1.5、y -0.7 |
| 8 | 持ったまま寄せる | 固定カメラが (0, 0) と答えた所から x に +11 cm、y に +2 cm | 成功 | x +0.5、y -1.6 |
| 1 | 持ったまま寄せる | 同上 | 失敗 | x +1.8、y -22.4 |
| 0 | 掴む前に覚える | 足さない | 成功 (トレイごと持ち上がる) | x -4.5、y +0.2 |
| 7 | 掴む前に覚える | 足さない | 成功 | x -7.6、y -0.2 |
| 2 | 掴む前に覚える | y に -4 cm | 失敗 | x -4.2、y -8.0 |
| 3 | 掴む前に覚える | y に -6 cm | 失敗 | x -4.3、y -9.1 |
| 9 | 掴む前に覚える | y に -6 cm | 失敗 | x -11.8、y -7.1 |
| 4、5 | 掴む前に覚える | y に -6 cm | 失敗 (右のボウルを運ぶ) | - |

ボウルを持ったまま寄せた 3 本 (init 1、6、8) は、"017" に書いたボウルを持っているときの固定カメラのずれ (トレイの中心から x に -6.7〜-15.0 cm、y に -6.0〜-9.8 cm) を、固定カメラが (0, 0) と答えた後の補正の量に使った。init 1 のコメントは、この補正が掴んだ縁のずれと画像のずれの両方を補うと書いている。y の +2 cm は、ボウルの中心が手先から +y に 6 cm あることと、y のずれ (-6.0〜-9.8 cm) を合わせた量と読める。この補正で、固定カメラのループが (0, 0) まで届いた 2 本はボウルをトレイの中心から 2 cm 以内に置いた。init 1 は、固定カメラのループが 2 cm × 10 回 (20 cm) の上限に達し (最後の答えは +y)、そこから補正したので、ボウルはトレイの手前に置かれた。

掴む前にトレイに合わせて置くときに -y にずらした 3 本 (init 2、3、9) は、018 の骨組みと同じ失敗をした。ボウルの中心はトレイの中心から y に -7.1〜-9.1 cm の所に下りてトレイの -y の縁に掛かり、指を開いて手先を上げると、ボウルが指に掛かって一緒に持ち上がった (最後の高さ 62.8〜63.2 cm)。018 の失敗 (y に -7.9〜-9.3 cm) と同じ位置である。ずらさなかった 2 本 (init 0、7) は 2 回とも成功し、020 と同じく、ずらさないことが合わせのずれを打ち消した。

init 4、5 は、先にトレイに合わせた後、トレイの上から左のボウルへ向かうときに、`in_wrist_view("the center of the bowl to pick up")` が 0.63、0.71 と答えた。プログラムはこれを手首の画像にボウルが写っているとみなして固定カメラでの寄せを飛ばし、手首の画像の向きだけで寄せた。手先は左のボウルから y に約 40 cm 離れていた。手首の画像の答えはほぼ左のボウルへ向かう -y だったが、ループは上限 (2 cm × 10 回、× 12 回) に達し、手先は左のボウルの +y 側 21〜24 cm にある右のボウルの近くで止まった。プログラムはそこをボウルの中心とみなして縁を掴み、2 本とも右のボウルをトレイに入れた。LIBERO は左のボウルを判定するので、失敗である。

## 結論

骨組みを回して分かったことを足しても、LLM の手順は task 60 で 4/10 (トレイごと持ち上げた 1 回を除くと 3/10) で、020 (6/10) より増えなかった。仮説は外れた。

足した知見のうち、ボウルを持っているときの固定カメラのずれは、3 本が補正の量として手順に入れ、固定カメラのループが届いた 2 本は成功した。ただしこの値は 018 で task 60 を回して測ったものなので、同じタスクで測った答えを手順に書き写したことになる。別のタスクで分かったことを持ち込めたことは示していない。

成功が増えなかったのは、10 本のうち 7 本が掴む前にトレイに合わせる手順を選び、その手順に要る知見 (何も持たずに合わせても 5〜8 cm 手前で止まる) が "017" に入っていなかったためである。この 7 本のうち、置くときにずらした 3 本は 018 と同じ位置に置いて失敗し、ずらさなかった 2 本は 020 と同じく打ち消しで成功した。残る 2 本は、トレイの上で `in_wrist_view` がボウルを見えると答えたので固定カメラでの寄せを飛ばし、手首の画像のループの上限が距離に足りずに、途中にあった右のボウルを掴んだ。019、021 の失敗と同じく、ループの上限が距離に足りないことが原因で、どの問いで寄せを打ち切るかの選び方がそれを招いた。

020、021、022 を通して、LLM の 1 本ごとの書き方 (合わせる時機、ずらすか、ループの上限、どの問いで寄せを打ち切るか) の違いが成否を分け、渡した知見の違いより大きかった。1 本ずつ 10 本の比較なので、知見を足した効果は task 61 (019 → 021) でも task 60 (020 → 022) でも、ばらつきと分けられない。
