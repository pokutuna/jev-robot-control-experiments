# 014 画像だけを渡す方策を、プリンの箱をトレイへ運ぶタスクで回す

## 課題

013 では、物体の位置の真値を文で渡す方策が task 61 (プリンの箱をトレイへ) を 10/10 で終えた。真値を外し、指示文、手先の状態、カメラ画像 2 枚だけを渡したとき、Jev が同じタスクで動く向きを決められるかを確かめる。予備実験 002 (task 60、黒いボウル) では 0/10 だったが、ボウルは指より大きく縁を挟まないと掴めないことが、向きの答えのよしあしと掴み方の失敗を分けにくくしていた。箱は指の開きより小さく、場面に 1 つしかないので、向きが正しければ箱の上で下ろして閉じるだけで掴める。

## 仮説

002 と同じ問いの形では、Jev は画像から世界座標の軸の向きを決められず、task 61 でも 0/10 になる。002 の静止画の確かめ (008) では、世界座標の向きの答えは手先と物の位置によらず偏っていた。この偏りは物の形によらないので、箱に替えても変わらない。

## 方法

方策は 002 と同じ `s1cap.jev_policy.JevDirectionPolicy` で、問いの形も 002 と同じである ([002 の README](../002-image-direction/README.md) の「方法」)。1 回の判断で Jev を 1 回呼び、x、y、z の軸ごとの向き (plus / stay / minus)、指 (開いた状態 / 閉じた状態)、タスクが終わったかを選ばせる。コードは選ばれた向きに各軸 2 cm 動かすだけで、何をどこへ動かすかはすべて Jev に任せる。判断の上限は 120 回。

002 から替えたのは次の点だけである。

| 項目 | 002 | 014 |
| --- | --- | --- |
| タスク | libero_90 60 (左の黒いボウル) | libero_90 61「pick up the chocolate pudding and put it in the tray」 |
| 画像の大きさ | 320 px | 448 px (012) |

真値は方策に渡さず、評価にだけ使う。init state は 0〜9。

```sh
uv run --env-file .env scripts/run_experiment.py run experiments/014-image-direction --inits 0-9
```

## 結果

[results.md](results.md) の表を要約する。

- 成功 0/10 (LIBERO の判定)。どのエピソードも判断の上限 (120 回) まで続いた
- 箱を持ち上げたエピソードは無い。手先と掴む点の最短距離は 26.7〜32.7 cm で、始めの位置 (箱から x に +14〜+18 cm、y に -18〜-22 cm、下に 22〜24 cm) からほとんど近づかなかった
- 1 エピソード: 120 回の判断 (呼び出しも 120 回)、平均 5660 step (283 秒)。1 回の呼び出しのレイテンシは平均 469 ms
- トークン: 1 エピソードで入力 26.6 万、出力 1.8 万

失敗の形は 10 エピソードとも 002 と同じだった。

1. 10 回とも最初の判断で指を閉じ、その後の 1200 回の判断でも指は「閉じた状態」を選び続けた
2. z は 1200 回中 1197 回が minus で、235〜830 step でテーブルの高さまで下りた
3. 指を閉じたままテーブルに押し付けて横へ引きずった。命令の 90〜92% が timeout で終わった (2 秒で 1 mm 以内に届かない)
4. 横の向きは、x で minus 978 回、plus 222 回、y で minus 912 回、plus 288 回だった。箱は始めの手先から +x、-y にあるので、x は箱から離れる向きに偏った。終わったときの手先は、箱から x に -30〜-42 cm 離れていた

`uv run scripts/direction_accuracy.py experiments/014-image-direction` で、行き先 (箱の中心) から 2 cm 以上ずれている軸について、送った移動の向きを数えた (10 エピソードの合計)。箱を持ち上げなかったので、すべて持ち上げる前の判断である。

| 方策 | 軸 | 判断 | 近づく | 動かさない | 遠ざかる |
|---|---|---|---|---|---|
| 014 (画像) | x | 1190 | 287 (24%) | 0 | 903 (76%) |
| 014 (画像) | y | 831 | 245 (29%) | 0 | 586 (71%) |
| 013 (真値の文) | x | 73 | 73 (100%) | 0 | 0 |
| 013 (真値の文) | y | 110 | 93 (85%) | 17 (15%) | 0 |

002 では x が近づく向きに 70%、y が遠ざかる向きに 73% だった。014 では x も y も遠ざかる向きが 7 割を超えた。

代表的な動画: [videos/init0.mp4](videos/init0.mp4) (左が固定カメラ、右が手首カメラ)。

## 結論

画像と座標系の説明を渡して世界座標の軸の向きを問う方策は、task 61 でも 0/10 で、仮説どおりだった。最初に指を閉じ、下りてテーブルに押し付けたまま横へ引きずる失敗の形も 002 と同じで、箱は指より小さく 1 つしかないという、002 より掴みやすい条件は効かなかった。向きの答えは箱の位置によらず偏り、x も y も 7 割以上が箱から遠ざかる向きだった。ただし偏る向きは 002 と同じではなく、x は 002 では近づく向きに 70% 偏っていた。偏りが物の形によらないという仮説の理由は、この結果では確かめられていない。

同じタスクで真値を文で渡した 013 (10/10、遠ざかる向きは 0 回) との差は、入力を真値から画像に替えたことだけではない。013 では、意図の選択肢と条件の真偽、行き先までの距離もコードが真値から作っていた ([002 の README](../002-image-direction/README.md) の「仮説」)。014 は、画像だけを渡し、何をどこへ動かすかをすべて Jev に任せたときの出発点として置く。
