# 019 段ごとの確かめの知見だけを渡し、LLM に task 61 の手順を書かせる

## 課題

017 では、人が手順の骨組みを書き、task 61 を 10/10 で終えた。ただし骨組みは、段ごとの小さな作業の確かめ (015、016) の知見だけでは足りず、タスクを最後まで回して見つけた失敗で 3 回直した。同じ動作の部品と、015、016 の知見だけを LLM に渡したとき、LLM が書く手順がどこまで動くかを確かめ、骨組みと比べる。

## 仮説

LLM は、015、016 の知見 (掴める範囲、行き先の言い方) を手順に取り入れ、掴む段は骨組みと同じくらい動く。017 で全体を回して初めて分かったこと (指を開くと置き場所を押す、物を持つと向きの答えがずれる) は渡していないので、置く段で骨組みより多く失敗する。

## 方法

方策は `s1cap.cap.CaPPolicy` で、プロンプトの「Facts」と「Reliability」の節に `KNOWLEDGE: "016"` (`src/s1cap/cap.py`) を入れ、init ごとに 1 本、計 10 本のプログラムを書かせた。プロンプトの全文は [programs/prompt.md](programs/prompt.md)。

- 渡したもの: 指示文、動作の部品 (017 の骨組みと同じ関数)、座標系、Jev の呼び出しと動作の上限、015 で測った掴める範囲 (箱の中心から y に ±1 cm なら 75 回中 73 回)、016 で測った行き先の言い方ごとの答えの傾向
- 渡していないもの: 017 の骨組み、手順、場面の物の位置と距離、017 で骨組みを直すのに使った知見
- コードを書く LLM は `deepseek/deepseek-v4.1-flash-1017`。例のコードは渡さず、実行結果を見せて書き直させることもしない
- 画像、カメラ、上限、init state は 017 と同じ

```sh
uv run --env-file .env scripts/generate_programs.py experiments/019-cap-task61 --inits 0-9
uv run --env-file .env scripts/run_experiment.py run experiments/019-cap-task61 --inits 0-9
```

## 結果

[results.md](results.md) の表と、プログラムと記録から読んだ値を要約する。

- 成功 5/10 (init 3、4、5、6、9)。017 の骨組み (4 つ目の版) は 10/10
- 1 エピソード: 平均 62.2 回の判断、Jev の呼び出し 41.0 回 (25〜80)、入力 4.1 万トークン。骨組み (63.5 回、38.2 回、4.0 万) とほぼ同じ
- プログラムの生成: 1 本あたり出力 1.8 万トークン (考える分を含む)、費用は 10 本で 0.098 USD

書かれた手順は、どれも「固定カメラで寄せる → 手首の画像で合わせる → 下ろす → 上げてから閉じる → 指の開きで掴めたかを見る → 運ぶ → 下ろす → 開く」で、015 の閉じる前に上げる量 (1.5 cm) と、016 の言い方 (「the chocolate pudding box」、「the box」、「the center of the tray」) を使っていた。違いは次の 2 点にあった。

- 置き場所に合わせる時機: 3 本 (init 0、4、9) は、箱を掴む前にトレイに合わせて位置を覚え、掴んだ後にその位置へ `move_to` で動いた。骨組みの 4 つ目の版と同じ手順を、知見から書いていた。残りの 7 本は、箱を持ったまま向きを問うてトレイへ寄せた
- ループの上限と 1 回に動く量: 本ごとに違い、1 つのループで向きを問う回数の上限は 3〜40 回、1 回に動く量は 1〜4 cm だった

失敗した 5 回は次のとおりだった。

| init | 失敗した段 | 起きたこと |
| --- | --- | --- |
| 1、7 | 運ぶ | 箱を掴んで持ち上げた後、固定カメラの答えでトレイへ寄せるループが上限 (2 cm × 20 回、2 cm × 12 回) に達した。答えは最後まで +y を向いていた。箱からトレイまでは y に約 44 cm あり、上限の動き (40 cm、24 cm) では届かず、トレイの手前に置いた |
| 2、8 | 掴む | 手首の画像で箱に合わせるループが上限 (8 回) に達し、答えはまだ -y を向いていた。指を閉じた所は箱の中心から y に +3.7〜+5.7 cm で、015 で掴めた範囲 (±1 cm) の外だった。やり直しでも同じ程度ずれ、3〜4 回とも掴めなかった |
| 0 | 置き場所を覚える | 先にトレイの位置を手首の画像の答えだけで覚えようとし、35 回で (0, 0) にならなかった。その後の箱への合わせで手先がトレイの上に残り、トレイの縁を掴んで 21 cm 持ち上げた |

5 回のうち 4 回は、ループの上限が、動く必要のある距離に足りなかった。LLM には場面の物の間の距離を渡していないので、上限を距離から決められない。骨組みでは、人が場面を見て上限を決めていた (固定カメラで 2 cm × 30 回 = 60 cm)。

骨組みを直すきっかけになった 2 つの失敗は、019 では目立たなかった。指を開いたときのトレイの持ち上げは成功した 5 回で 0〜3.0 cm で、017 の 1 つ目の版 (21〜22 cm) のようには持ち上がらなかった。箱を持ったまま手首の画像で x を合わせた 3 本 (init 3、5、6) は、どれも成功した。

代表的な動画: [videos/init9.mp4](videos/init9.mp4) (成功、先にトレイの位置を覚える手順)、[videos/init7.mp4](videos/init7.mp4) (失敗、トレイの手前に置く)。左が固定カメラ、右が手首カメラ。

## 結論

段ごとの確かめの知見だけを渡すと、LLM の手順は 5/10 で、骨組み (10/10) より少なかった。ただし仮説と違い、失敗は置く段の向きの答えのずれではなく、ループの上限の不足に多く現れた (掴む段 2 回、運ぶ段 2 回)。LLM は 015、016 の知見 (言い方、閉じる前に上げる量) を取り入れたが、場面の大きさを知らないので、何回まで向きを問うかを決められなかった。骨組みは、人が決めた上限がこの欠けを補っていた。

置き場所に先に合わせて位置を覚える手順は、骨組みでは 018 の失敗の後に人が入れたものだが、LLM は 10 本中 3 本で知見から書いた。
