# 001 真値を文で渡す (先行事例の問いの形を移す)

## 課題

Jev をロボットの制御に使った先行事例 (OpenRoboto の incremental_policy[^openroboto]) は、別のロボットと場面で、物体の位置を文で渡して Jev に意図と動く向きを選ばせた。この問いの形が LIBERO のこのタスクでも働くかは分かっていない。

## 仮説

先行事例の問いの構造 (意図を選ぶ呼び出しと、軸ごとの向きと指を選ぶ呼び出し) を移し、真値から作った目標、位置合わせの条件の真偽、条件と動きの対応を文で渡せば、Jev はそれを読んでタスクを終える。

先行事例のコードや問いの文をそのまま動かす再現ではない。問いの構造を移し、目標、条件、歩幅はこのタスクに合わせて書いた。以後の実験 (真値を渡さず画像を渡す) と比べる基準にする。

## 方法

| 項目 | 内容 |
| --- | --- |
| タスク | libero_90 60「pick up the black bowl on the left and put it in the tray」 |
| init state | 0〜9 |
| Jev に渡すもの | 状態の JSON。手先、ボウル、トレイの位置 [mm] (真値)、掴む手先の位置と離す手先の位置、その差、位置合わせの真偽、指の開き、直前の意図、直前の命令の結果。画像は渡さない |
| Jev への問い | 1 回目: 意図 (approach / grasp / lift / carry / lower / release / withdraw / finish)。2 回目: x、y、z の軸ごとの向き (negative / hold / positive) と指 (open / hold / close)。各軸の問いの文に今の座標、目標の座標、差 [mm] を書く |
| 呼び出し | 1 回の判断で 2 回。1 回目で意図を選ばせ、選ばれた意図 (`selected_intent`) を state に足して、2 回目で x、y、z の向きと指をまとめて問う。指の答えが今の状態と違えば、その判断では指の命令だけを送り、移動は送らない |
| 判断の上限 | 120 回 |

実装は `src/s1cap/jev_text.py` (`JevTextPolicy`)、dataflow は [dataflow.yml](dataflow.yml)。

## Jev が決めていることと、コードが決めていること

| Jev | コード |
| --- | --- |
| 意図 | 物体の位置 (真値) と、掴む位置 (ボウルの縁: 中心から +y に 6 cm、上に 3 cm)、離す位置、運ぶ高さ |
| 軸ごとの向き (3 択) | 位置合わせができたか (`grasp_pose_reached`、`over_tray` など) の真偽。意図の説明文はこの真偽を条件に書いてある |
| 指を開くか閉じるか | 1 歩の大きさ (目標までの距離が 12 mm 未満なら 4 mm、25 mm 未満なら 8 mm、それ以上は 20 mm) |
| タスクを終えたか (finish) | 手先を下向きにそろえる最初の命令、指の命令を移動と別に送ること |

Jev の仕事は、文に書かれた差の符号を読んで向きを選ぶことと、真偽の条件に合う意図を選ぶことに近い。何をどこへ動かすかは、コードが真値から計算して文に書いている。

## 結果

[results.md](results.md) の表を要約する。

- 成功 10/10 (LIBERO の判定)
- 1 エピソード: 平均 65.3 回の判断 (59〜85)、Jev の呼び出し 128.6 回、1339 step (67 秒)。初めて成功と判定されたのは平均 1071 step
- 1 回の判断のレイテンシ (2 回の呼び出しの合計) は平均 684 ms (エピソードごとの平均で 670〜693 ms)。呼び出しごとには、意図が 338 ms、向きと指が 345 ms
- トークン: 1 エピソードで入力 23.3 万 (21.0〜30.5 万)、出力 1.4 万
- 意図の内訳 (10 エピソードの合計): carry 211、approach 201、lift 73、lower 67、withdraw 62、grasp 10、finish 10、release 9。掴み直しは無く、grasp は各エピソード 1 回だった

### 横の向き

`uv run scripts/direction_accuracy.py experiments/001-text-baseline --offset 0,0.06` で、行き先 (持ち上げる前は掴む位置、持ち上げた後は離す位置。どちらも中心から +y に 6 cm) から 2 cm 以上ずれている軸について、送った移動の向きを数えた (10 エピソードの合計)。

| 段 | 軸 | 判断 | 近づく | 動かさない | 遠ざかる |
|---|---|---|---|---|---|
| 持ち上げる前 | x | 18 | 18 (100%) | 0 | 0 |
| 持ち上げる前 | y | 46 | 41 (89%) | 5 (11%) | 0 |
| 持ち上げた後 | x | 96 | 46 (48%) | 50 (52%) | 0 |
| 持ち上げた後 | y | 250 | 200 (80%) | 50 (20%) | 0 |

遠ざかる向きは一度も選ばなかった。持ち上げた後の「動かさない」は、運ぶ高さまでまっすぐ上げる判断 (lift) である。

代表的な動画: [videos/init0.mp4](videos/init0.mp4) (左が固定カメラ、右が手首カメラ)

## 気づいたこと

- 掴む位置の付近や運ぶ途中で、x が ±4 mm で行き来することがある。位置合わせの許容幅 (8 mm) の境目で、差の符号が判断ごとに変わるため。成功には影響しなかった
- init 0、1、2、4〜9 で、指を開いてボウルを離した直後から 1〜6 秒ほど、トレイが 2〜12 cm 浮いた (浮いていたのは 24〜127 step) (表の「トレイの持ち上げ」)。手先は離す高さで止まっており、トレイを押してはいない。どのエピソードでも最後にはトレイは元の高さに戻り、LIBERO の判定も成功のままだった。原因は確かめていない
- 終わり方の `policy_closed` は、policy ノードが end を送った直後に止まり、sim が end を受け取る前に入力が閉じたときの記録である。どれも Jev が finish を選んで終えている。init 9 からは policy ノードが sim の終了を待つようにしたので `policy_end` になる

## 結論

- 真値から作った目標と条件の真偽、手書きの制御則 (歩幅、掴む位置、運ぶ高さ) を文で渡せば、Jev は意図と軸の向きを選ぶだけでこのタスクを 10/10 で終えた。先行事例の問いの構造は、このタスクでも働いた
- このとき Jev がしている判断は「差の符号と真偽の読み取り」に近く、知覚は担っていない。何をどこへ動かすかは、コードが真値から計算している
