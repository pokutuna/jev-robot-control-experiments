# アウトライン

課題: Jev という Decision モデルの画像入力を利用してロボットアームで LIBERO タスクが解けるか

- Jev というモデルが 2026-09-15 に TypeSafe AI から公開されて話題になった
- Jev は LLM を転用して高速な構造化された意思決定が行える、これをロボットタスクに応用できないか
- 公開からすぐに Web 上ではロボットアームの動作に利用する事例がいくつも見られた(本文では例にリンクする)
  - ただしわかりやすく成功している例では、環境の情報(privileged information, ground-truth state)や対象オブジェクトの座標を入力として与えており、難易度が低い課題設定と思われる
- 2026-10-14 の Jev 1.14 preview では画像入力を行えるようになった
  - この画像入力をロボットアームの操作に利用できないか、試行錯誤してレポートにする
  - 環境情報を制限し、ロボットアームの手先の位置と指の開き、手首カメラ、環境カメラを利用してタスクを解くことを目標とする
- まとめ(完成後に書く)

---

実験 001〜011 は予備実験 (libero_90 task 60、黒いボウルをトレイへ) として残す。レポートに使う実験は 012 から、下のタスクで行う。「予備実験:」で始まる行は予備実験の結果と、そこから立てた見込みや下調べで、レポートには含めない。

- 採用するタスク・シーン (選んだ理由と意図は [scenes.md](scenes.md))
  - 本筋: libero_90 task 61「pick up the chocolate pudding and put it in the tray」(LIVING_ROOM_SCENE4)
    - プリンの箱は場面に 1 つしかなく、指の開き (8 cm) より小さい。物への向きを問えば、その向きがほぼ掴む場所への向きになるので、Jev の答えを動きに使えるかを、掴み方の補正なしで確かめられる
    - 予備実験: task 60 と同じシーン。ボウルは指より大きく縁しか掴めないこと、同じ形のボウルが隣にあることが、Jev の答えのよしあしと掴み方の失敗を分けにくくした
  - 運ぶ物の切り替え: 同じシーンの task 62「pick up the salad dressing and put it in the tray」と task 60「pick up the black bowl on the left and put it in the tray」
    - シーン、置き場所、カメラを変えずに運ぶ物だけが替わるので、4、5 の手順がタスクに固有の値を埋め直すだけで動くかを確かめられる
  - 高難易度: libero_goal task 3 を改変した「open the top drawer and put the cream cheese inside」
    - 運ぶ前に、閉じた引き出しを開ける段が 1 つ加わる。入れる物は本筋と似た平たい箱 (クリームチーズ) にして、差を引き出しを開けることに絞る
  - 環境カメラ位置
    - クォータービュー (卓の斜め上から見下ろす固定カメラ) で、運ぶ物と置き場所が両方写ること
    - 引き出しのタスクでは、今の置き方だと棚が画像の左端で切れるので、取っ手が写るように置き直す
  - 解像度: 固定カメラと手首カメラの画像を 448 px にする (012)
    - 入力トークンは画素数にほぼ比例し、レイテンシは 896 px まで変わらない。448 px で箱の形と位置が分かり、「写っているか」の確信度が 0.92〜0.94 になる
- 実験
  - 1. 物体の位置の真値を文で渡して、タスクが解けることを確かめる (task 61)
    - 予備実験: 10/10。公開事例と同じ形の問いなら解ける (001)
  - 2. 真値を渡さず、画像 (固定カメラ、手首カメラ) だけを渡す (task 61)
    - 予備実験: 0/10。世界座標の軸の向き (+x、−y など) を問うと、違う向きへ動く (002)
  - 3. どのようなガイドを足すと Jev が働くかを、タスクの中の段ごとの小さな作業で探る。タスクの完了はここでは扱わない
    - 画像の中の向き: 画像の手先の位置に印を描き、「印から見て物はどちらか」を画像の中の向きで問う
      - 予備実験: 向きは答えられる。静止画で確かめると、4 cm 以上ずれていれば y の向きは 90 問中 74〜90 問で正しく、2 cm ほど手前で止まる (003、008)
      - 予備実験: 下りる時機と指を閉じる時機は、Jev には決められない (003、004)
    - 掴めるか: 箱の上に手先を合わせて下ろし、指を閉じれば掴めるか。どれだけのずれまで掴めるか
      - 予備実験: プリンの箱の y の幅は 4.6 cm で、指の開きとの差から許されるずれは片側約 1.7 cm。Jev が 2 cm 手前で止まる傾向が残ると、ここで落ちる見込み
    - 言い方: 対象の言い方を替えて、目的の物に近づく向きを答えるか
      - 対象の表現: 「chocolate pudding box」「brown box」「box」など
      - 方向: 「左の」「右の」が通用するか。同じ形のボウルが 2 つある task 60 で、左右のボウルを指して問う
      - 予備実験: 行き先の言い方で答えが変わる。「the center of the bowl to pick up」では y の 81% が近づく向きだったが、「the black bowl on the left」では 27% だった (008)
  - 4. Jev には 3 で分かった問いだけをし、手順は人が書く
    - 物を運ぶタスクに共通の骨組み (対象にアームを近づける → 下ろす → 掴む → 持ち上げる → 目的地に近づける → 下ろす → 置く) と、動作の部品、Jev への問いの型を、人が 1 度だけ書く
    - タスクに固有の値 (対象と行き先の言い方、掴む場所と高さ、終わりの判定) を、人が task 61 に合わせて埋める
    - 骨組みを変えずに運ぶ物を替え、タスクに固有の値だけを埋め直して動くかを確かめる
      - task 62 (ドレッシングの瓶): 背が高く (14.6 cm)、どの高さを掴むかで倒れやすさが変わる
      - task 60 (左の黒いボウル): 指より大きく縁しか掴めない。同じ形のボウルが右にあり、「左の」で区別する
    - 予備実験: 掴む、運ぶ、置くの段と、段を切り替える条件を人が書く: 9/10 (006)
    - 予備実験: ボウルは指より大きく、縁しか掴めない。縁を行き先にして問う: 10/10 (004-2、010)。物の位置と掴むべき場所は別
    - 予備実験: 005、006 では、段の並び、段を切り替える条件、歩幅や高さの数値、縁への 6 cm の補正、掴めたかの判定、行き先の言い方、終わりの判定をすべてコードに書いていた。Jev が決めたのは、画像の中の向き、トレイが見えるか、ボウルがトレイに入ったかだけだった
    - 予備実験: Jev に段を選ばせる呼び出しは、コードの条件表とほぼ同じ答えを返しただけだった (005)
  - 5. 人が書いた手順を LLM に書かせる (Code as Policies)
    - LLM には動作の部品と、3 で分かった Jev の得意・不得意だけを渡し、タスクに固有の値を埋めさせる。task 61、62、60 のそれぞれで、4 の人が書いたものと比べる
      - task 60 では、ボウルの縁を掴むことを LLM が物の形から決められるかを見る
    - 骨組みにない段を LLM が組めるかを、6 の引き出しのタスクで見る
    - 予備実験: 006 の知識をプロンプトに渡す: 2/10 (007)
    - 予備実験: 行き先の言い方だけを 006 にそろえる: 7/10 (009)。下がった分の多くは言い方による
    - 予備実験: 010 までの知見を足す: 6/10。縁を掴む手順は 10 本すべてのプログラムが取り入れた (011)
  - 6. 前段の動作を加える: 引き出しを開けてクリームチーズを入れる
    - まず静止画で、取っ手が固定カメラに写るか、Jev が取っ手への向きを答えられるかを確かめる
    - 取っ手へ寄る → 掴む → 引く → 離す、の段を LLM が組めるかを見る
    - 予備実験: 引き出しの中は卓から約 17 cm 上にある。取っ手を掴む、引いて開ける、高い所へ入れる動作は、どれもまだ試していない
