# dora-rs で LIBERO をノードに分け、ロボットの知覚だけで方策を動かす

## Goal

LIBERO のシミュレーションを dora-rs の sim / policy / evaluator ノードに分け、方策 (policy) がロボットの知覚 (カメラ画像、手先の状態) だけを入力に動く構成を作る。手書きの方策で閉ループが回り、Jev や CaP の方策を差し替えて載せられるところまでを目指す。

## Approach & Rules

### Architecture

- 講義 (応用編1 第 4〜6 回) の「ロボットは非同期分散システムで、センサ、方策、ロボットを別ノードにする」構成に合わせる。第 6 回で扱った dora-rs を使う
- ノード:
  - sim: LIBERO を進め、画像 (agentview、手首)、ロボットの状態、物体の真値を流す。命令を受け、内部の制御器で目標を保ち続ける (実機のロボットドライバと同じ役)
  - policy: 画像とロボットの状態だけを購読し、命令を出す。手書き → Jev → CaP の順に差し替える
  - evaluator: 真値で成功を判定し、動画と記録を残す
- ロボットの知覚 (画像、手先の位置と向き、指の開き、関節角) と、シミュレータの真値 (物体の姿勢、引き出しの関節値、成功判定) を分ける。policy は真値を購読しない。比較用の「JSON 入力」条件のときだけ明示して渡す
- 物体の位置を画像から推定する処理は作らない。方策は知覚から直接動作を決める
- 通信部分を差し替えられるようにし、ノードの中身 (`src/s1cap/`) は dora に依存させない

### Constraints

- リポジトリは提出物で public。リポジトリ外のリソースは環境変数でパスを渡し、何をどこに置くかを `docs/setup.md` に書く
- uv で管理し、使える範囲で新しい版を使う。版を絞るときは理由を `pyproject.toml` と `docs/setup.md` に書く
- 開発機は macOS (Apple Silicon)。robosuite の描画は CGL に差し替え済み (`src/s1cap/sim.py` の `_use_cgl_offscreen`)
- 締切は 2026-11-02 10:00。課題の合格条件は「ロボットがタスクを実行している動画」

### 判断基準

- 01 か 03 で半日以上詰まったら dora-rs をやめ、同じノード構成を自前の API レイヤ (同じプロセス、またはソケットや HTTP) で作る
- 実時間で進める非同期モードを主にする。04 で、目標を渡して sim の制御器に任せる命令の形式なら、方策の推論が 2 秒かかっても結果が変わらなかった (待つ間ロボットは止まる)。同期モードは、方策が画像を見て step ごとに直す使い方が必要になったときに足す

### Conventions

- 作業で分かった制約や落とし穴は `wiki/` に書く (`.claude/rules/wiki.md`)
- コミットはユーザに頼まれたときだけ行う

## Outcome

- LIBERO を dora-rs の sim / policy / evaluator ノードに分け、policy をロボットの知覚 (画像、手先の状態) だけで動かす構成ができた。手書き、Jev、CaP 型のモックの policy を差し替えて載せられる
- 非同期モード (sim は 20 Hz で進み、命令を待つ間ロボットは止まる) で、Jev の推論待ちがあっても結果は変わらない
- Jev に画像だけで 3 次元の移動の向きを選ばせると成功しなかった。画像の中の位置関係なら安定して答える。この結果を受けて、題材を「画像だけで Jev がロボットを動かせるか、何を補えば動くか」に組み直し、後続の Bunch で実験として進める

## Leftover

- 複数エピソードの実行と集計 (05) は、後続の Bunch で実験ごとに回す仕組みとして作る
- CaP の policy (07) は、後続の Bunch の最後の実験で扱う
- 終わり方が `policy_closed` と `policy_end` のどちらになるかが、policy と sim の終わる順で変わる
- `dora run` を `dataflows/` で実行すると、`dataflows/out/` と `dataflows/outputs/` ができる
