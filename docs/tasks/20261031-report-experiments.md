# レポートの実験 (012 以降) を本筋のタスクで回す

## Goal

[docs/report-outline.md](../report-outline.md) の実験 1〜6 を、libero_90 task 61 (プリンの箱をトレイへ) を本筋に、task 62、60 と引き出しのタスクで回し、レポートと動画に使える結果を `experiments/` に残す。

## Approach & Rules

### 実験の条件

- 実験 001〜011 は予備実験 (task 60) として残し、レポートに使う実験は 012 から番号を振る。012 は解像度の確認 (済み)
- タスクとシーンは [docs/scenes.md](../scenes.md)。固定カメラは quarterview、画像は 448 px (012)
- init state 0〜9 で回す。時間が足りなければ 0〜4 に減らし、README に書く
- 方策には真値を渡さない。真値は評価にだけ使う。物体の位置を画像から推定する処理は作らない。方策は知覚から直接動作を決める
- 3 は段ごとの小さな作業を静止画や短い操作で確かめる。タスクの完了は扱わない
- 4 は物を運ぶタスクに共通の骨組みを人が 1 度だけ書き、タスクに固有の値 (対象と行き先の言い方、掴む場所と高さ、終わりの判定) だけをタスクごとに埋める。特定のタスクの解き方をコードに書かない
- 5 は LLM に動作の部品と 3 の知見だけを渡し、4 の人が埋めた値と比べる
- 6 は静止画の確認から始め、結果を見て先に進めるかを決める

### 構成

- 実験に共通の実装は `src/s1cap/`、dora のノードは `nodes/`、実験ごとの dataflow と記録は `experiments/NNN-slug/` ([experiments/README.md](../../experiments/README.md))
- 新しい dataflow は `IMAGE_SIZE=448`、`FIXED_VIEW=quarterview` にし、sim の `sim_state` を evaluator につなぐ。動画は `scripts/render_episode.py` で後から描き直すので、録画は代表的なものだけでよい
- Jev は Decision モデルと呼ぶ (レポートの用語)

### Constraints

- リポジトリは提出物で public。リポジトリ外のリソースは環境変数でパスを渡し、`docs/setup.md` に書く。API キーは `.env` にだけ置く
- `uv run --env-file .env` で実行する。dora の実行は同時に 1 つだけ
- 締切は 2026-11-02 10:00。レポートと動画の時間を残すため、実験は 2026-11-01 中に切り上げる。1、2、4 (task 61) を最低限とする

### Conventions

- 作業で分かったことは `wiki/` に書く (`.claude/rules/wiki.md`)
- 結果は動画か真値で確かめてから報告する
- 実験の README は 課題、仮説、方法、結果、結論、次へ の節で書く (012 と同じ)
- コミットはユーザに頼まれたときだけ行う
